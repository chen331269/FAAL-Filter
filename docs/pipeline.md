# 处理流程

一帧输入从进来到出去，经过哪些步骤、每一步归谁管。配合 [`smoothing.md`](smoothing.md) 一起看。

> ## ⚠️ 调参前先看自动校准
>
> 如果上层（JSM 的 AUTO_CALIBRATE_GYRO，或任何手柄驱动的漂移补偿）开着自动校准，
> 它会把这个速度以下的一切当作零偏慢慢减掉——**包括玩家真实但缓慢的转动**。
>
> 表现为"慢速移动被吃掉、像死区"，而数据里看到的输入**已经是减完之后的值**，
> 从它出发去分析滤波器，会得出完全错误的结论（我们就为此浪费了一整天）。
>
> 调 FAAL 之前，先确认自动校准的状态。要慢速精度就关掉它，让 FAAL 的漂移保持来兜底。

## 总览

```
入口（每帧一次）
  1. dt 钳位到 [1ms, 50ms]
  2. 需要复位 → 清空所有状态
  3. speed = |V|                     ← 2D 或 3D 向量长度
  4. 矢量检测：当前方向 vs 参考方向 → forceSuppress（真/假）
  5. 更新参考方向 s_smoothDir        ← 比较之后才更新
  6. w = smoothTierWeight(speed)     ← 0 = 全平滑，1 = 全直通
  7. 逐轴调用 doFilter(v, dt, forceSuppress, w, speed)

逐轴
  a. 峰值跟踪      peak 跟随 |v| 上升，按 peakDecayTime 衰减
  b. 下降速率      dropSpeed = Δv / (dt·1000) / (peak + 0.001)
  c. 迟滞系数      上升 2.9 ms / 快降 29 ms / 慢降 65 ms
  d. 漂移保持      |v| < 0.15 持续 0.2 s → 直接返回 0，清空状态
  e. 斜率抑制      rawSuppress = clamp(dropSpeed · 灵敏度) ^ 曲线
  f. 过零覆盖      符号翻转 + 幅度跳变 → rawSuppress = 1
  g. 反转覆盖      forceSuppress → rawSuppress = 1
  h. 迟滞平滑      suppressHyst 向 rawSuppress 靠拢
  i. 分层平滑      out = v·w + OneEuro(v·(1−w), fc = fc_min + beta·speed)
  j. 施加抑制      out *= (1 − suppressHyst)
  k. 冻结窗口      suppressHyst > 阈值 → out *= freezeMul，持续 N 毫秒
```

## 三个区间

| 速度 | 谁在管 | 效果 |
|---|---|---|
| < 0.15°/s 持续 0.2 s | 漂移保持 | 输出精确为 0 |
| 0.15 – T | **一层平滑** | 只有低通，抑制被门限关掉 |
| T – 2T | 两者交接 | 平滑渐弱、抑制渐强 |
| > 2T | **抑制** | 斜率 / 过零 / 反转全力 |

`T = smoothThreshold`。交接用 smoothstep，所以跨过 T 时不会有突变的台阶。

## 为什么低速不做判断

`0.5°/s` 的运动，逐帧速度变化只有 `0.13°/s`；而手抖的幅度也在 `0.1~0.3°/s`。两者的统计特征完全重叠：

> 在低速段，"意图"和"抖动"在信号里不可区分。

所以这一段的策略是**不判断**——交给低通把抖动压成缓慢漂移，而不是用一个靠不住的判据去猜"这一帧该不该压"。FAAL 早期版本在这里照样判断，结果是低速时压得时多时少，手感上像"有东西在偷偷吃掉输入"。

## 三个设计约束

**① 抑制和滤波互不反馈**

抑制只读原始输入，滤波只读原始输入，最后相乘：

```cpp
out = OneEuro(...) * (1 - suppressHyst);
```

滤波器的状态在抑制期间保持"热"的（喂的是原始值），所以抑制一解除，输出立刻是真实值，没有爬升过程。

**② 权重和截止频率是帧级共享的**

`w` 和 `fc` 都由**整个向量的速度**决定，两个轴用同一组系数。如果各轴自己算，快轴和慢轴的滞后不同，画圆会变成椭圆、方向被拉偏。

**③ 帧率无关**

所有时间常数都通过 `1 - exp(-dt / tau)` 换算，`dt` 在入口被钳位到 `[1, 50] ms`。同一个参数在 60 Hz 和 1000 Hz 下行为一致。

## 唯一的二值判断

除了漂移保持，其余全是连续量。矢量反转检测虽然输出布尔值，但它的效果被交接门限约束住了：低于 T 时 `rawSuppress *= 0`，触发也不起作用。

所以实际上：

- **低速**：连续平滑，无二值开关
- **高速**：抑制状态机（有迟滞，但输入本身足够可信）

## 参数

| 参数 | 默认 | 管什么 |
|---|---|---|
| `smoothThreshold` | 0 | 平滑与抑制的交接速度（deg/s）。0 = 不平滑 |
| `oneEuroFcMin` | 2.0 | 低速时的平滑强度（Hz） |
| `oneEuroBeta` | 0.08 | 平滑随速度放开的速率 |
| `hystRiseTime` | 0.0029 | 抑制上升快慢 |
| `hystFallTime` | 0.065 | 抑制释放快慢 |
| `peakDecayTime` | 0.065 | 峰值衰减 |
| `signChangeThr` | 1.5 | 过零检测的幅度门限 |
| `dirChangeAngleRad` | — | 反转判定角度 |
| `dirChangeMagRatio` | — | 反转判定幅度 |
| `driftThreshold` / `driftHoldTimeSec` | 0.15 / 0.2 | 静止判定 |
| `freezeDurationSec` / `freezeOutMul` | — | 冻结窗口 |

## 调试建议

出问题时的排查顺序：

1. **低速发黏** → 先把 `smoothThreshold` 设为 0（关平滑），确认是不是低通太强
2. **抖动透出来** → 提高 `smoothThreshold`，让抑制更早介入
3. **快速甩枪发钝** → 检查 `smoothThreshold` 是否过大（抑制在高速仍在动作）
4. **静止时漂移** → 检查 `driftThreshold` 是否过低

`FAAL_TRACE` 记录了每帧的输入和输出，可以在外部复现整个流程。
