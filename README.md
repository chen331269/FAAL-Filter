# FAAL Filter

**Frame-rate Adaptive Attenuation Layer** — 为陀螺仪输入设计的去抖与反向抑制滤波器

---

## 💡 开发初衷：从《斯普拉遁》说起

作为一个热衷于在 PC 端折腾陀螺仪玩 FPS 的玩家，我一直在寻找完美的防抖方案。但我发现，现有的主流防抖算法基本都是走死板的“传统信号处理”套路，它们**忽略了一个事实：人是人，人是有生理缺陷的。** 

你不能要求一个在紧张对枪中的人保持手部绝对稳定，这太反人类了。传统的低通滤波器只能逼着玩家在“高延迟”和“剧烈抖动”之间二选一。

直到我玩了《斯普拉遁》（Splatoon），我观察到了它极其**人性化**的处理方式：
1. **动态震荡抑制**：当你因为紧张而手部震荡时，它会极其强烈地压制准星移动。
2. **甩枪余韵处理**：甩枪结束后的回弹被很好地抑制，手感就像**非牛顿流体**——你越用力甩，它越稳定。
3. **场景自适应**：它会根据使用场景动态调节，比如腰射近战时强防抖，狙击开镜时微防抖，甚至扣下扳机那一刻会瞬间去掉防抖。

我萌生了在 PC 端复现这种手感的想法。值得一提的是，经过无数次的逆向体验，我发现它**绝不是**通过传统的信号处理手法实现的——我试了大量的常规算法，只能在防抖和延迟之间痛苦权衡。它更像是一种**“增益缩放”**：滤波器直接作用于灵敏度缩放后的效果，所以手感上几乎没有延迟。

带着这个猜想，我开始和 AI 不断探讨、经历无数次迭代，终于打磨出了现在这个像样的实现——**FAAL**。

---

## 这是什么

FAAL 是一个轻量级、帧率无关的陀螺仪信号处理器，用于解决体感瞄准中三类最难处理的抖动：

- **静止漂移**（手持微颤）
- **甩枪回弹**（快速甩动结束后信号反向振荡）
- **按键抖动**（按下/松开扳机时的高频噪声）

它最初为 [JoyShockMapper](https://github.com/Electronicks/JoyShockMapper) 开发，现在是一个独立的 C++ 模块，**无外部依赖，单头文件 + 单 cpp**，可以直接嵌入任何体感输入管线。

---

## 为什么需要它

传统去抖方案有两种极端：

| 方案 | 问题 |
|---|---|
| **固定低通**<br>`out = α·in + (1-α)·prev` | 平滑好了但**甩枪延迟**；跟手了但**静止抖** |
| **固定死区**<br>信号绝对值 `< 阈值 → 0` | 抖动没了但**微调被吃掉**；死区边界有**跳变感** |

**体感输入的需求是矛盾的**：
- 静止时：要**强平滑**，任何微动都是噪声
- 慢速跟随时：要**低延迟**，微调是精准瞄准
- 快速甩枪时：要**跟随**，不能拖尾
- 甩枪结束时：要**强抑制**，防反冲回弹

没有任何一个固定参数能同时满足。**FAAL 的思路是：让滤波器根据"当前正在发生什么"自动切换策略。**

---

## 核心特性

- ✅ **帧率无关** —— 所有时间常数、阈值都归一化到 1000Hz 基准，60Hz / 120Hz / 500Hz / 1000Hz 下行为一致
- ✅ **自适应抑制** —— 甩枪后自动进入"黏滞"模式，正常跟随时自动进入"跟手"模式，无阈值跳变（像非牛顿流体）
- ✅ **One Euro 平滑** —— 借用 Casiez 2012 的经典自适应低通，静止时稳、快速时准
- ✅ **矢量反转检测** —— 3D 方向突变检测，替代分轴符号翻转（避免画圆变画方）
- ✅ **零依赖** —— 只需要 `<math.h>`，无 STL、无框架

## 工作原理

FAAL 的每轴处理管线：

```text
输入 ω
  │
  ├──► [1] 峰值跟踪      peakValue 记录最近的运动峰值，随时间衰减
  │
  ├──► [2] dropSpeed     (|ω| 的每秒衰减率，归一化到 1000Hz)
  │
  ├──► [3] rawSuppress   = pow(dropSpeed × sensitivity, curve)
  │                      决定"这一帧应该抑制多少"
  │
  ├──► [4] 符号翻转检测  单帧内 |Δω| 突增 → 强制满抑制
  │
  ├──► [5] 矢量反转检测  3D 方向角突变 → 三轴同步抑制
  │
  ├──► [6] 自适应滞回    suppressHyst 用上升/下降时间常数更新
  │                      fall = fastFall + (slowFall - fastFall) × suppressHyst
  │                      ↑ 甩枪后 fall 慢（黏），正常时 fall 快（跟手）
  │
  ├──► [7] One Euro      fc = fc_min + β·|dω|，自适应低通
  │
  └──► [8] 施加抑制       out = smoothed × (1 - suppressHyst)
```

### 自适应 fall 的关键

传统的滞回滤波器用固定时间常数。FAAL 的核心创新是**让抑制强度自己决定解除速率**：

```cpp
fallFactor = fastFallFactor + (slowFallFactor - fastFallFactor) * suppressHyst;
```

- 抑制弱（`suppressHyst ≈ 0`，正常跟随）→ fall 快（29ms）→ **跟手**
- 抑制强（`suppressHyst ≈ 1`，甩枪刚结束）→ fall 慢（65ms）→ **黏滞保抑制**
- 中间平滑插值，无阈值跳变

**`suppressHyst` 是状态量，不是每帧重算的**——上一帧的抑制值决定这一帧用多快的解除速率，标准的反馈控制结构。

## 参数

FAAL 向用户暴露**极简参数**，全部有时间或比例语义，没有"魔法数字"：

### 抑制系统（3 个）

| 参数 | 默认 | 含义 |
|---|---|---|
| `hystRiseTime` | 0.0029 | 抑制快进时间（秒）—— 抑制从 0 到满 |
| `hystFallTime` | 0.065 | 抑制慢出上限（秒）—— 满抑制时的解除时长 |
| `peakDecayTime` | 0.065 | 峰值衰减时间（秒）—— 独立跟踪参数 |

派生（自动，用户不可改）：
```text
hystFallFastTime = hystFallTime × 0.446   // 无抑制时的快出时间
```

### 独立参数（6 个）

| 参数 | 默认 | 含义 |
|---|---|---|
| `dropSensitivity` | 2.4 | 减速抑制灵敏度（调大 = 更晚触发，调小 = 更敏感） |
| `dropCurve` | 2.0 | 抑制曲线形状（物理自然值） |
| `signChangeThr` | 0.5 | 符号翻转触发阈值 |
| `freezeDurationSec` | 0.024 | 反转后冻结时长（秒） |
| `enableVectorReversal` | off | 矢量反转检测开关 |
| `dirChangeAngleRad` | 1.2 | 矢量反转角度阈值（弧度） |

### 平滑参数（2 个）

| 参数 | 默认 | 含义 |
|---|---|---|
| `oneEuroFcMin` | 2.0 | One Euro 基线截止频率（Hz） |
| `oneEuroBeta` | 0.08 | One Euro 速度反馈系数 |

**总共约 11 个可调参数**——相比大多数体感滤波器动辄 30+ 参数，这已经是最精简的配置。

## 帧率无关保证

体感输入的回报率从 60Hz（低端手柄）到 1000Hz（高端鼠标/键盘）差异巨大。如果滤波器用"每帧"作为时间单位，同样的参数在不同回报率下手感完全不同。

FAAL 的解决方案：

1. **时间常数归一化**：所有滞回系数用 `1 - exp(-dt / tau)` 计算
2. **速度归一化**：`dropSpeed` 和 `signChange` 除以 `dt × 1000`，映射到 1000Hz 基准
3. **状态累积**：`freezeRemainingSec` 和 `stillTimeSec` 存**秒**，每帧 `-= dt`，不是帧计数
4. **dt 防御**：入口 `dt = clamp(dt, 1e-3, 0.05)`，异常 dt 优雅退化

**结果**：1000Hz 下调好的参数在 60Hz 下行为一致，反之亦然。用户换设备不用重新调参。

## 使用

### 基本用法

```cpp
#include "faal_filter.h"

// 初始化（可选，通常自动）
ResetFaalFilter();

// 每帧调用
float gx = imu.gyroX;
float gy = imu.gyroY;
faal_filter(gx, gy, dt);   // 2 轴
// 或
faal_filter(gx, gy, gz, dt);  // 3 轴

// gx, gy 已被就地修改为滤波后的值
```

### 设置参数

```cpp
FaalParams p;
p.hystRiseTime = 0.0029f;
p.hystFallTime = 0.065f;
p.peakDecayTime = 0.065f;
p.oneEuroFcMin = 2.0f;
p.oneEuroBeta = 0.08f;
// ... 其他参数
SetFaalParams(p);
```

### 复位

```cpp
// 设备断开、切换、重新校准时调用
ResetFaalFilter();
```

### ⚠️ 在 JoyShockMapper (JSM) 中的最佳实践位置

经过实际测试，**滤波器的插入位置对最终手感影响极大**。为了获得最佳的“非牛顿流体”防抖效果，请务必将 `faal_filter()` 放在以下位置：

*   ✅ **正确位置：主线程空间转换（Gyro Space / 映射到鼠标 X/Y）之后，灵敏度计算（Sensitivity / Accel Curve 增益）之前。**
    *   *原因*：此时信号已经是你真正想要移动的方向（X/Y），且没有被灵敏度增益放大误差。在这里处理，物理意义最准确。
*   ❌ **错误位置：空间转换之前（处理原始 IMU 轴）。**
    *   *原因*：原始轴受重力/姿态影响，滤波逻辑会把正常的倾斜误判为抖动，导致**手感极其奇怪，甚至出现剧烈抖动**。

## 适用场景

FAAL 特别适合以下场景：

- ✅ **体感瞄准**（FPS、TPS 游戏中的陀螺仪鼠标控制）
- ✅ **VR / AR 手柄**（双手 6DoF 追踪的姿态滤波）
- ✅ **遥控器、空中鼠标**（低延迟 + 抗抖）
- ✅ **手持云台、动作捕捉**（高精度姿态跟踪）

不太适合：

- ❌ **纯位置追踪**（FAAL 面向角速度信号）
- ❌ **极低频信号**（< 5Hz，比如缓慢呼吸检测，FAAL 会被误认为"静止"而输出 0）
- ❌ **高精度工业测量**（FAAL 有抑制机制，会丢失部分真实信号）

## 与类似方案对比

| 方案 | 帧率无关 | 自适应 | 甩枪防回弹 | 参数复杂度 |
|---|---|---|---|---|
| 一阶低通 | ❌ | ❌ | ❌ | 低 |
| 卡尔曼滤波 | ✅ | ❌ | ❌ | 高 |
| One Euro Filter | ✅ | ✅ | ❌ | 中 |
| 死区 + 低通 | ❌ | ❌ | ❌ | 低 |
| **FAAL** | ✅ | ✅ | ✅ | **中** |

FAAL 相比 One Euro 的**额外价值**是"甩枪结束后主动保抑制"——这是 One Euro 本身不具备的能力。
