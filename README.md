# FAAL Filter

**Frame-rate Adaptive Attenuation Layer** — 为陀螺仪输入设计的去抖与反向抑制滤波器

---

## 💡 开发初衷：从《斯普拉遁》说起

作为一个热衷于在 PC 端折腾陀螺仪玩 FPS 的玩家，我一直在寻找完美的防抖方案。但我发现，现有的主流防抖算法基本都是走死板的“传统信号处理”套路，它们**忽略了一个事实：人是人，人是有生理缺陷的。** 

你不能要求一个在紧张对枪中的人保持手部绝对稳定，这太反人类了。传统的低通滤波器只能逼着玩家在“高延迟”和“剧烈抖动”之间二选一。

直到我玩了《斯普拉遁》（Splatoon），我观察到了它极其**人性化**的处理方式：
1. **动态震荡抑制**：当你因为紧张而手部震荡时，它会极其强烈地压制准星移动。
2. **甩枪余韵处理**：甩枪结束后的回弹被很好地抑制，手感就像**非牛顿流体**——你越用力甩，它越稳定。
3. **场景自适应**：它会根据使用场景动态调节，比如腰射近战时强防抖，狙击开镜时微防抖，甚至扣下扳机那一刻会瞬间去掉防抖。

我萌生了在 PC 端复现这种手感的想法。值得一提的是，经过无数次的逆向体验，我发现它**绝不是**通过传统的信号处理手法实现的——我试了大量的常规算法，只能在防抖和延迟之间痛苦权衡。它更像是一种**“增益缩放”**：滤波器直接作用于灵敏度缩放后的效果，所以手感上几乎没有延迟。

带着这个猜想，我开始和 AI 不断探讨、经历无数次迭代，终于打磨出了现在这个像样的实现——**FAAL**。

## 快速上手（单头文件 C99）

`faal.h` 是完整的实现，声明和代码在同一个文件里（stb 风格）：

```c
#define FAAL_IMPLEMENTATION   /* 只在一个翻译单元里定义 */
#include "faal.h"

Faal *f = faal_new();
FaalParams p;
faal_defaults(&p);
p.dropSensitivity = 1.0f;   /* 线性 drop，当前实测手感 */
faal_set_params(f, &p);

float v[2] = { 10.0f, 3.0f };
faal_process(f, v, 2, 0.001f);   /* 原地滤波，2 或 3 轴 */
faal_free(f);
```

- 纯 C99，只依赖 `math.h` / `stdlib.h` / `string.h`
- 无全局状态、无线程、无锁
- `faal_new` 走 malloc；`faal_init` 用调用方给的内存（嵌入式）
- `sizeof(Faal)` = 224 字节、`sizeof(FaalParams)` = 100 字节（x64）

### 接进别的语言

| 语言 | 方式 |
|---|---|
| C / C++ | 定义 `FAAL_IMPLEMENTATION` 后包含 |
| Python | 编成 DLL，ctypes 包装 |
| C# | 编成 DLL，P/Invoke |
| Rust | `build.rs` 里用 `cc` 编一个只包含 `faal.h` 的 TU |

DLL 构建（Windows）：

```powershell
cl /O2 /LD /DFAAL_BUILD_DLL /c faal_shim.c /Fe:faal.dll
```

`faal_shim.c` 只有两行：`#define FAAL_IMPLEMENTATION` 和 `#include "faal.h"`。
不定义 `FAAL_BUILD_DLL` 时导出表会是空的。

### 参数扩展

`FaalParams` 第一个字段固定是 `size`（调用方填 `sizeof(FaalParams)`）。以后加参数
追加在末尾，老调用方传小的 `size` 时库只读它认得的字段。

### 等价性

`reference/` 是最早的 C++ 实现，**已冻结**，只作为历史基线保留。

2026-11-15 ~ 11-18 期间 C 库做过这些改动，两者不再是逐帧等价：移除平滑、移除静止模块、冻结改为只由事件点火、反转改双模式。因此早期那份"40 万帧、最大差 4.24e-05"的对照**不再成立**，不要再引用。

当前的回归手段是 `_faal_c/suppress_only_test.cpp`（8 项冒烟检查）：常数直通、过零压制与恢复、冻结窗口 × `freezeOutMul`、冻结被 hyst 续期、120° 反转触发、`revMinDps` 挡住静止噪声、纯减速不点火冻结、20 万随机样本无 NaN。
## 这是什么

FAAL 是一个轻量级、帧率无关的陀螺仪信号处理器，用于解决体感瞄准中三类最难处理的抖动：

- **静止漂移**（手持微颤）
- **甩枪回弹**（快速甩动结束后信号反向振荡）
- **按键抖动**（按下/松开扳机时的高频噪声）

它最初为 [JoyShockMapper](https://github.com/Electronicks/JoyShockMapper) 开发，现在是一个独立的 **C99 单头文件**实现，无外部依赖，可以直接嵌入任何体感输入管线。当前主要宿主是 [MotionStudio](https://github.com/) 的自定义运动滤波器（Rhai 脚本，见 `hosts/motionstudio/`）。

注意：**静止漂移不再由 FAAL 处理**。库内的静止判定已于 2026-11-18 移除——它和手抖落在同一幅度区间，无法区分，触发时还会把整条抑制链重置。静止时的零偏交给宿主的噪声门或游戏内死区。

## 为什么需要它

传统去抖方案有两种极端：

| 方案 | 问题 |
|---|---|
| **固定低通**<br>`out = α·in + (1-α)·prev` | 平滑好了但**甩枪延迟**；跟手了但**静止抖** |
| **固定死区**<br>信号绝对值 `< 阈值 → 0` | 抖动没了但**微调被吃掉**；死区边界有**跳变感** |

**体感输入的需求是矛盾的**：
- 静止时：要**强平滑**，任何微动都是噪声
- 慢速跟随时：要**低延迟**，微调是精准瞄准
- 快速甩枪时：要**跟随**，不能拖尾
- 甩枪结束时：要**强抑制**，防反冲回弹

没有任何一个固定参数能同时满足。**FAAL 的思路是：让滤波器根据"当前正在发生什么"自动切换策略。**

---

## 核心特性

- ✅ **帧率无关** —— 所有时间常数、阈值都归一化到 1000Hz 基准，60Hz / 120Hz / 500Hz / 1000Hz 下行为一致
- ✅ **自适应抑制** —— 甩枪后自动进入"黏滞"模式，正常跟随时自动进入"跟手"模式，无阈值跳变（像非牛顿流体）
- ⛔ **平滑层已移除（2026-11-15）** —— FAAL 只做抑制，平滑交给宿主或独立滤波器；保留 `oneEuro*` 字段只为 API 兼容
- ✅ **矢量反转检测（双模式）** —— 过零检测在场时退回 `|sin θ|` 当补强（干净的 180° 交给过零）；过零缺席时用幅值比独立负责 180°。两者都只看方向，不碰连续转动
- ✅ **零依赖** —— 只需要 `<math.h>`，无 STL、无框架

## 工作原理

FAAL 的每轴处理管线：

```text
输入 ω
  │
  ├──► [1] 峰值跟踪      peakValue 记录最近的运动峰值，随时间衰减
  │
  ├──► [2] dropSpeed     (|ω| 的每秒衰减率，归一化到 1000Hz)
  │
  ├──► [3] rawSuppress   = min(dropSpeed × sensitivity, 1)
  │                      曲线只有两档：1 = 线性，2 = 再平方（宿主无 pow）
  │                      决定"这一帧应该抑制多少"
  │
  ├──► [4] 符号翻转检测  单帧内 |Δω| 突增 → 强制满抑制
  │
  ├──► [5] 矢量反转检测  与 7.5ms 低通的参考方向比夹角 →
  │                      双模式（|sin| 或幅值比）→ 触发一次、吸收参考
  │
  ├──► [6] 自适应滞回    suppressHyst 用上升/下降时间常数更新
  │                      fall = fastFall + (slowFall - fastFall) × suppressHyst
  │                      ↑ 甩枪后 fall 慢（黏），正常时 fall 快（跟手）
  │
  └──► [7] 施加抑制       out = ω × (1 - suppressHyst)，冻结窗口内再乘 freezeOutMul
```

### 自适应 fall 的关键

传统的滞回滤波器用固定时间常数。FAAL 的核心创新是**让抑制强度自己决定解除速率**：

```cpp
fallFactor = fastFallFactor + (slowFallFactor - fastFallFactor) * suppressHyst;
```

- 抑制弱（`suppressHyst ≈ 0`，正常跟随）→ fall 快（29ms）→ **跟手**
- 抑制强（`suppressHyst ≈ 1`，甩枪刚结束）→ fall 慢（65ms）→ **黏滞保抑制**
- 中间平滑插值，无阈值跳变

**`suppressHyst` 是状态量，不是每帧重算的**——上一帧的抑制值决定这一帧用多快的解除速率，标准的反馈控制结构。

## 参数

FAAL 向用户暴露**极简参数**，全部有时间或比例语义，没有"魔法数字"：

### 抑制系统（3 个）

| 参数 | 默认 | 含义 |
|---|---|---|
| `hystRiseTime` | 0.0029 | 抑制快进时间（秒）—— 抑制从 0 到满 |
| `hystFallTime` | 0.065 | 抑制慢出上限（秒）—— 满抑制时的解除时长 |
| `peakDecayTime` | 0.065 | 峰值衰减时间（秒）—— 独立跟踪参数 |

派生（自动，用户不可改）：
```text
hystFallFastTime = hystFallTime × 0.446   // 无抑制时的快出时间
```

### 独立参数（7 个）

| 参数 | 默认 | 含义 |
|---|---|---|
| `dropSensitivity` | 2.4（库）/ 1.0（脚本） | 减速抑制灵敏度，线性档下越大越强 |
| `dropCurve` | 2.0（库）/ 1.0（脚本） | 曲线：1 = 线性，2 = 二次（更陡） |
| `signChangeThr` | 0.5 | 符号翻转触发阈值；**设为 0 同时关掉过零**（此时反转自动切到幅值比模式） |
| `freezeDurationSec` | 0.024 | 冻结时长（秒）；只有事件能点火 |
| `freezeOutMul` | 0.1 | 冻结期输出倍数 |
| `enableVectorReversal` | 0 | 矢量反转检测开关 |
| `dirChangeMagRatio` | 0.3 | 反转门限，**语义随模式变**：过零在场时是 `\|sin θ\|` 比例，缺席时是"新速度 / 参考速度" |
| `dirChangeAngleRad` | 1.2 | 反转角度阈值（弧度）；实测手感值 0.9 |
| `revMinDps` | 0（库） | 方向判定的绝对速度下限；0 = 不设（静止噪声会触发，换来"钉住"效果） |
| `revFreezeMinDps` | 0 | 过零缺席时，参考速度达到多少才允许触发**点火冻结**（否则只压制） |

### 平滑参数（已移除）

平滑层在 2026-11-15 从库里移除。`oneEuroFcMin`、`oneEuroBeta`、`smoothThreshold`、`speedLpMs` 仍留在 `FaalParams` 里只为 API 兼容，`do_filter()` 不再读它们。

原因：抑制和平均不该住在同一个模块里。平滑会把抑制的动作抹圆，还把可感知的延迟加到每一条路径上；而它真正压掉的抖动，在 1 dps / 8 Hz 时只有约 0.06°（40 counts/° 下两三个计数）。

当前第 9 步就是 `out = v;`，剩下的只有 `(1 - suppressHyst)` 与冻结窗口。设计经过与当时的测量见 [docs/smoothing.md](docs/smoothing.md)（顶部已标废弃）。

MotionStudio 侧的两个宿主脚本在 [`hosts/motionstudio/`](hosts/motionstudio/)，那份 README 说明了阶段、参数和校验方式。

**实际生效约 13 个可调参数**——相比大多数体感滤波器动辄 30+ 参数，这已经是最精简的配置。

## 帧率无关保证

体感输入的回报率从 60Hz（低端手柄）到 1000Hz（高端鼠标/键盘）差异巨大。如果滤波器用"每帧"作为时间单位，同样的参数在不同回报率下手感完全不同。

FAAL 的解决方案：

1. **时间常数归一化**：所有滞回系数用 `1 - exp(-dt / tau)` 计算
2. **速度归一化**：`dropSpeed` 和 `signChange` 除以 `dt × 1000`，映射到 1000Hz 基准
3. **状态累积**：`freezeRemainingSec` 存**秒**，每帧 `-= dt`，不是帧计数
4. **dt 防御**：入口 `dt = clamp(dt, 1e-3, 0.05)`，异常 dt 优雅退化

**结果**：只要 `dt` 可信，1000Hz 下调好的参数在 60Hz 下行为一致，反之亦然。

### 前提：dt 必须可信

帧率无关是**条件成立**的结论，不是无条件保证。归一化把 `dt` 当成真时间，`dt` 一旦失真，误差会被原样放大到每一个时间常数上：

| 情况 | 后果 |
|---|---|
| 时间戳只有毫秒精度，1000Hz 下大量 `dt = 0` | 状态不推进；若被 clamp 成 1 ms，则时间被**凭空拉长** |
| 设备重发相同报文（NS 模式的第三方手柄常见） | 数据没变但时间在走：滤波器以为手在动，实测是静止；峰值、滞回、冻结全按**包率**而不是物理时间衰减 |
| 同一帧发两次，包率翻倍 | 所有时间常数**等效减半**（冻结 24 ms → 12 ms，fall 65 ms → 32 ms） |

因此宿主必须做两件事：**按内容去重**（完全相同的数据不推进状态），以及 **`dt <= 0` 时直接丢弃样本**而不是兜底到 1 ms。MotionStudio 的脚本已按内容去重；C 库目前没有，接入方需要自己在外面处理。

## 使用

### 基本用法

```c
#include "faal.h"          /* 一个 TU 里定义 FAAL_IMPLEMENTATION */

Faal *f = faal_new();
FaalParams p;
faal_defaults(&p);
faal_set_params(f, &p);

float v[2] = { imu.gyroX, imu.gyroY };
faal_process(f, v, 2, dt);    /* 就地修改；3 轴传 3 */
faal_free(f);
```

### 设置参数

```c
FaalParams p;
faal_defaults(&p);            /* 先拿默认值，再改想要的字段 */
p.hystFallTime   = 0.065f;
p.peakDecayTime  = 0.065f;
p.dropSensitivity = 1.0f;
p.dropCurve       = 1.0f;
faal_set_params(f, &p);
```

### 复位

```c
/* 设备断开、切换、重新校准时调用 */
faal_reset(f);
```

### ⚠️ 在 JoyShockMapper (JSM) 中的最佳实践位置

经过实际测试，**滤波器的插入位置对最终手感影响极大**。为了获得最佳的“非牛顿流体”防抖效果，请务必将 `faal_filter()` 放在以下位置：

*   ✅ **正确位置：主线程空间转换（Gyro Space / 映射到鼠标 X/Y）之后，灵敏度计算（Sensitivity / Accel Curve 增益）之前。**
    *   *原因*：此时信号已经是你真正想要移动的方向（X/Y），且没有被灵敏度增益放大误差。在这里处理，物理意义最准确。
*   ❌ **错误位置：空间转换之前（处理原始 IMU 轴）。**
    *   *原因*：原始轴受重力/姿态影响，滤波逻辑会把正常的倾斜误判为抖动，导致**手感极其奇怪，甚至出现剧烈抖动**。

## 适用场景

FAAL 特别适合以下场景：

- ✅ **体感瞄准**（FPS、TPS 游戏中的陀螺仪鼠标控制）
- ✅ **VR / AR 手柄**（双手 6DoF 追踪的姿态滤波）
- ✅ **遥控器、空中鼠标**（低延迟 + 抗抖）
- ✅ **手持云台、动作捕捉**（高精度姿态跟踪）

不太适合：

- ❌ **纯位置追踪**（FAAL 面向角速度信号）
- ❌ **极低频信号**（< 5Hz，比如缓慢呼吸检测，FAAL 会被误认为"静止"而输出 0）
- ❌ **高精度工业测量**（FAAL 有抑制机制，会丢失部分真实信号）

## 这段历程：为什么最终把平滑拿掉了（2026-11-15 ~ 11-18）

FAAL 最初是"平滑 + 抑制"两层：One Euro 负责压抖，峰值跟踪负责减速抑制。实测下来这套组合的矛盾无法在同一组参数下调和——**平滑的收益全在低速（静止不抖），代价全在高速（甩枪发黏）**，而体感瞄准要的恰恰是"低速稳、高速利落"。

2026-11-15 把平滑层整体剥离后，结论很直接：**延迟从"参数取舍"变成"可见的固定值"**，实测"没有延迟了，视角地震还被大幅压制"。于是本项目定调：**FAAL 只做抑制，平滑交给宿主或下游**。

此后几天都在打磨"抑制"这一件事，三次关键修正：

1. **冻结只能由事件点火**（过零 / 矢量反转）。之前 drop 的电平也能点火，导致一次急停的减速把冻结续期，第二次甩枪正好落进窗口被钳住——这就是"吞枪"。
2. **矢量反转修了两次**。原判据 `|sin θ|` 在干净的 180° 掉头上恒为 0，等于恰好瞎掉最该抓的动作；改成幅值比能抓，但会与过零重叠。最终做成 **双模式**：过零在场时退回 `|sin|` 当补强，过零缺席时用幅值比全权负责 180°。
3. **发现"智能死区"**。矢量检测在静止时因方向不连贯而频繁触发，`hyst` 打满、输出归零——准星被"钉住"；而连贯的慢速微调几乎不触发，不被吃掉。这个性质不是设计出来的，是意外的副产品，但它比传统死区聪明，因此被单独记为待抽出的模块（`HANDOFF §23`）。

`faal_B_rev_mag_v4.rhai` 是这一路线的第一个"手感对了"的版本：双模式 + 一次性触发 + 冻结门（过零缺席时，参考速度不足则只压不冻）。
